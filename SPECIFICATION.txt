1. システム概要
-------------------------------------------------------------------------------

MobiLendは、情報企画課が社内のモバイル通信端末を管理するためのWeb
アプリケーションである。端末台帳、貸出、返却、紛失、返却期限、利用者の
在籍状態を一元管理し、返却忘れや端末紛失の早期発見を支援する。

  +------------------+          +---------------------------+
  | 管理者           |          | 利用者                    |
  | (情報企画課)     |          | (各部署の社員)            |
  +--------+---------+          +-------------+-------------+
           |                                      |
           | HTTPS / 社内ネットワーク             |
           +-------------------+------------------+
                               |
                    +----------v----------+
                    |   MobiLend Web App  |
                    |   Python / Flask    |
                    +----------+----------+
                               |
                    +----------v----------+
                    |      SQLite DB      |
                    | users/devices/loans |
                    +---------------------+


-------------------------------------------------------------------------------
2. 目的と対象範囲
-------------------------------------------------------------------------------

[目的]

  - モバイル通信端末の現在位置と利用者を明確にする。
  - 貸出日と返却期限を記録し、期限超過を可視化する。
  - 返却済み、貸出中、紛失の履歴を保持する。
  - 退職者への誤貸出を防止する。
  - 管理者と一般利用者の操作権限を分離する。

[対象範囲]

  - USBタイプおよびWiFiタイプのモバイル通信端末
  - ユーザー、端末、貸出履歴の登録・参照
  - 返却および紛失の記録
  - 返却期限超過の画面表示
  - 端末タイプ別の総台数および貸出可能台数の表示
  - 貸出中利用者への確認メール作成・送信
  - 有効期限付きURLからの返却、紛失、返却期限延長の登録
  - 操作感確認用の大規模デモデータおよび公開用CSV

[対象外]

  - Slack、Teams等への自動通知
  - 外部の人事システム、認証基盤との連携
  - 端末の位置情報追跡
  - 業務データの汎用CSV入出力、帳票出力
  - パスワード変更、再発行機能
  - 端末情報の編集、削除、利用停止解除

3. ユーザー種別と権限
-------------------------------------------------------------------------------

  +------------------------------+----------+----------+
  | 機能                         | 管理者   | 利用者   |
  +------------------------------+----------+----------+
  | ログイン                     |    O     |    O     |
  | 全端末の参照                 |    O     |    O     |
  | 自分の貸出状況・履歴の参照   |    O     |    O     |
  | 全利用者の貸出状況の参照     |    O     |    X     |
  | 端末の新規登録               |    O     |    X     |
  | 契約プランの登録・修正       |    O     |    X     |
  | 契約プランの廃止・再開       |    O     |    X     |
  | 貸出の新規登録               |    O     |    X     |
  | 返却の登録                   |    O     |    X     |
  | 紛失の登録                   |    O     |    X     |
  | 利用状況確認メールの送信     |    O     |    X     |
  | メールURLからの返却登録      |    X     |    O     |
  | メールURLからの紛失登録      |    X     |    O     |
  | メールURLからの期限延長      |    X     |    O     |
  | ユーザーの新規登録           |    O     |    X     |
  | ユーザーの退職状態変更       |    O     |    X     |
  +------------------------------+----------+----------+

管理者はrole="admin"、利用者はrole="user"として管理する。
retired=1のユーザーはログインおよび新規貸出の対象選択を不可とする。
メールURLからの操作は通常ログインとは別に、対象貸出と有効期限を限定した
ランダムトークンによって認可する。

4. 画面構成・画面遷移
-------------------------------------------------------------------------------

                         +----------------+
                         | ログイン画面   |
                         +-------+--------+
                                 |
                  +--------------+--------------+
                  | 認証成功                    | 認証失敗
                  v                             v
        +--------------------+         +--------------------+
        | ダッシュボード     |         | エラーメッセージ   |
        +--+----+----+----+--+         | ログイン画面継続   |
           |    |    |    |            +--------------------+
           v    v    v    v
    +--------+ +----+ +--------+ +----------+
    |端末台帳| |貸出| |プラン  | |ユーザー  |
    |        | |履歴| |管理    | |管理      |
    +--------+ +----+ +--------+ +----------+
                       管理者のみ  管理者のみ

[共通ヘッダー]

  - システム名
  - ダッシュボード、端末台帳、貸出履歴へのナビゲーション
  - 管理者の場合のみ契約プラン管理、ユーザー管理へのナビゲーション
  - ログインユーザー名、部署、権限
  - ログアウトボタン

[4.1 ログイン画面]

入力:
  - ユーザーID（必須）
  - パスワード（必須）

処理:
  - ユーザーIDとパスワードを照合する。
  - パスワードはハッシュ値と照合し、平文では保存しない。
  - 退職済みユーザーのログインを拒否する。
  - 成功時はセッションを再生成してダッシュボードへ遷移する。

[4.2 ダッシュボード]

管理者表示:
  - 登録端末数
  - 貸出中端末数
  - 貸出可能端末数
  - 期限超過件数
  - USB / WiFiごとの総台数および貸出可能台数
  - 現在の全貸出一覧（返却期限の昇順）

利用者表示:
  - ログインユーザー本人が利用中の端末一覧
  - 端末番号、タイプ、貸出日、返却期限、期限超過状態

[4.3 端末台帳]

表示項目:
  - 端末番号
  - タイプ（USB / WiFi）
  - 電話番号
  - 契約プラン
  - 利用状況（貸出可能 / 貸出中 / 利用停止）
  - 貸出中の場合は利用者名と返却期限

管理者操作:
  - 新規端末の登録
  - 契約プランマスターで利用中のプランから選択する。

[4.4 貸出履歴]

表示項目:
  - 端末番号、端末タイプ
  - 利用者名、部署名
  - 貸出日、返却期限
  - 状態（貸出中 / 期限超過 / 返却済み / 紛失）
  - 備考

管理者操作:
  - 貸出可能端末と在籍中利用者を選択して新規貸出を登録する。
  - 貸出中の記録を返却済みに変更する。
  - 貸出中の記録を紛失に変更する。
  - 貸出中の利用者へ利用状況確認メールを作成・送信する。

利用者操作:
  - 自分の貸出履歴のみ参照できる。

[4.5 契約プラン管理]

表示項目:
  - プラン名、説明
  - 状態（利用中 / 廃止済み）
  - 設定済み端末数

管理者操作:
  - 契約プランの新規登録
  - プラン名、説明の修正
  - 利用中プランの廃止
  - 廃止済みプランの利用再開

廃止済みプランは新規端末登録の選択肢に表示しない。すでに設定されて
いる端末との関連は維持し、端末台帳に「廃止済み」と表示する。

[4.6 ユーザー管理]

表示項目:
  - ユーザーID
  - ユーザー名
  - 部署名
  - メールアドレス
  - 権限
  - 在籍状態

管理者操作:
  - ユーザーの新規登録
  - 在籍から退職済みへの変更
  - 退職済みから在籍への復帰
  - ログイン中の自分自身は退職済みに変更できない。

[4.7 メールURL端末状況登録]

表示項目:
  - 利用者名
  - 端末番号、端末タイプ
  - 現在の返却期限
  - 現在の貸出状態

利用者操作:
  - 本日付で返却済みとして登録する。
  - 紛失として登録し、対象端末を利用停止にする。
  - 現在の返却期限より後の日付へ返却期限を延長する。

アクセス条件:
  - メール本文の有効期限付きランダムURLからアクセスする。
  - URLは対象の貸出1件だけを操作可能とする。
  - 既定の有効期限は発行から72時間とする。
  - 返却済みまたは紛失済みの場合は追加操作を受け付けない。

5. 業務フロー
-------------------------------------------------------------------------------

[貸出フロー]

  +------------+    +----------------+    +----------------+
  | 端末選択   | -> | 利用者選択     | -> | 日付・備考入力 |
  +------------+    +----------------+    +--------+-------+
                                                  |
                                                  v
  +------------+    +----------------+    +----------------+
  | 貸出完了   | <- | 貸出履歴作成   | <- | 入力値検証     |
  +------------+    +----------------+    +----------------+

以下の場合は貸出を登録しない。

  - 端末が存在しない、利用停止、またはすでに貸出中
  - 利用者が存在しない、退職済み、または管理者アカウント
  - 貸出日または返却期限が未入力
  - 返却期限が貸出日より前

[貸出状態遷移]

                        返却登録
                  +------------------+
                  |                  v
  +-----------+    |          +-------------+
  | 貸出登録  +--->+ 貸出中   |  返却済み   |
  +-----------+               +-------------+
                  |
                  | 紛失登録
                  v
              +-----------+
              |   紛失    |
              +-----------+
                  |
                  +--> 対象端末を利用停止(active=0)に変更

「期限超過」は独立した保存状態ではない。status="borrowed"かつ
due_dateがシステム日付より前の場合に、画面表示時に動的判定する。

[利用状況確認メールフロー]

  +--------------+    +----------------+    +----------------------+
  | 管理者が送信 | -> | トークン発行   | -> | SMTP送信 / EML出力   |
  +--------------+    +----------------+    +----------+-----------+
                                                       |
                                                       v
  +--------------+    +----------------+    +----------------------+
  | 履歴を記録   | <- | 状態を更新     | <- | 利用者がURLで操作     |
  +--------------+    +----------------+    +----------------------+

  - トークンは暗号学的乱数で生成し、データベースにはSHA-256ハッシュのみ保存する。
  - メール送信時にnotified操作履歴を記録する。
  - SMTP未設定のローカル検証ではinstance/outboxへEMLファイルを出力する。
  - 期限延長は現在の返却期限より後、かつシステム日付以降のみ許可する。

-------------------------------------------------------------------------------
8. 入力チェック・エラー処理
-------------------------------------------------------------------------------

[端末登録]

  - 端末番号、タイプ、電話番号、契約プランはすべて必須とする。
  - タイプはUSBまたはWiFiのみ許可する。
  - 契約プランはマスターに登録された利用中プランのみ許可する。
  - 端末番号の重複を許可しない。

[契約プラン登録・修正]

  - プラン名は必須とする。
  - プラン名の重複を許可しない。
  - 説明は任意とする。
  - 廃止しても既存端末との関連は削除しない。

[ユーザー登録]

  - ユーザーID、ユーザー名、初期パスワード、部署名、メールアドレス、権限は必須とする。
  - メールアドレスには@を含む値を指定する。
  - 権限はadminまたはuserのみ許可する。
  - ユーザーIDの重複を許可しない。
  - 画面上の初期パスワード最小文字数は8文字とする。

[貸出登録]

  - 端末、利用者、貸出日、返却期限は必須とする。
  - 返却期限は貸出日以降とする。
  - 利用停止中または貸出中の端末は登録不可とする。
  - 退職済み利用者は登録不可とする。

[メールURLからの期限延長]

  - 新しい返却期限は必須とする。
  - 新しい返却期限は現在の返却期限より後とする。
  - 新しい返却期限はシステム日付以降とする。
  - 貸出状態がborrowed以外の場合は操作不可とする。

処理結果は成功、警告、エラーのフラッシュメッセージとして画面に表示する。

9. セキュリティ仕様
-------------------------------------------------------------------------------

  +----------------------+-----------------------------------------------+
  | 項目                 | 対応                                          |
  +----------------------+-----------------------------------------------+
  | パスワード保存       | Werkzeugによるソルト付きハッシュ             |
  | セッション           | Flask署名付きCookie                          |
  | CSRF                 | 全POSTリクエストでトークンを照合             |
  | 認証                 | セッション内の内部ユーザーIDで判定           |
  | 認可                 | admin_requiredで管理者専用処理を保護         |
  | メールURL認可         | 256bit相当の乱数トークンと有効期限で限定     |
  | トークン保存         | SHA-256ハッシュのみをデータベースへ保存      |
  | SQLインジェクション  | プレースホルダー付きSQLを使用                |
  | HTMLエスケープ       | Jinja2の自動エスケープを使用                |
  +----------------------+-----------------------------------------------+

本番環境では以下を必須とする。

  - MOBILEND_SECRET_KEYに十分長いランダム値を設定する。
  - テストアカウントの初期パスワードを変更または削除する。
  - HTTPSを終端できるリバースプロキシ配下で運用する。
  - debugモードを無効にする。
  - instanceディレクトリとデータベースファイルのアクセス権を制限する。
  - SMTPパスワード、検証用メールアドレスはinstance/local.envまたは環境変数に
    保存し、Gitリポジトリへ登録しない。
  - MOBILEND_BASE_URLには利用者がHTTPSで到達可能なURLを設定する。

11. 実行環境・起動方法
-------------------------------------------------------------------------------

[構成]

  - Python 3
  - Flask 3.1.3
  - SQLite 3
  - HTML5 / CSS3
  - SMTP（実メール送信時のみ）

[セットアップ]

  > python -m venv .venv
  > .venv\Scripts\Activate.ps1
  > python -m pip install -r requirements.txt
  > python app.py

起動後、ブラウザで http://127.0.0.1:5000 を開く。
初回起動時にinstance/mobilend.sqlite3とテストデータを自動作成する。
旧バージョンのデータベースにはemail列、メール操作用テーブルを自動追加する。

[メール設定]

Git管理外のinstance/local.envまたは環境変数で設定する。

  - MOBILEND_MAIL_MODE: file（EML出力）またはsmtp（実送信）
  - MOBILEND_BASE_URL: メール本文に挿入するシステムURL
  - MOBILEND_MAIL_FROM: 差出人メールアドレス
  - MOBILEND_SMTP_HOST / MOBILEND_SMTP_PORT: SMTP接続先
  - MOBILEND_SMTP_USE_TLS: STARTTLS使用有無
  - MOBILEND_SMTP_USERNAME / MOBILEND_SMTP_PASSWORD: SMTP認証情報
  - MOBILEND_ACTION_TOKEN_HOURS: メールURLの有効時間（既定72）
  - MOBILEND_TEST_RECIPIENT: ローカル検証用の既定送信先
  - MOBILEND_DEMO_SCALE: 大規模デモデータ補充の有効・無効

MAIL_MODE=fileの場合はinstance/outbox/*.emlへメール内容を保存する。

[自動テスト]

  > python -m pytest -q

テスト対象:

  - 管理者ログインと期限超過表示
  - 利用者本人のデータ分離と管理画面へのアクセス拒否
  - 退職済みユーザーのログイン拒否
  - 貸出登録と返却登録
  - CSRFトークン未指定リクエストの拒否
  - 確認メールのEML生成と送信先
  - メールURLからの期限延長、返却、紛失および端末利用停止
  - 大規模データの件数、武将名の一意性、再実行時の冪等性
  - ダッシュボードのUSB / WiFi別集計表示
  - 既存のプロジェクトテスト

13. 制約・今後の拡張候補
-------------------------------------------------------------------------------

[現行制約]

  - SQLiteを使用するため、大規模な同時接続には適さない。
  - Flask内蔵開発サーバーは本番用途に使用しない。
  - 期限超過メールは管理者の手動送信であり、定期自動送信ではない。
  - 操作監査ログはメール通知・期限延長・返却・紛失を対象とし、その他の
    マスター操作は保持していない。
  - 紛失後の発見・利用再開を画面から操作できない。
  - GitHub Pagesは静的デモ専用であり、Flask、SQLite、SMTP機能は動作しない。

[拡張候補]

  +--> 返却期限前・超過時のメール/Teams/Slack定期自動通知
  +--> 社内SSOおよび人事マスター連携
  +--> 端末・ユーザーの編集、CSV一括登録
  +--> 貸出申請・管理者承認ワークフロー
  +--> 全操作監査ログと貸出履歴検索
  +--> QRコードによる端末選択・返却処理
  +--> PostgreSQLへの移行
  +--> 定期バックアップとリストア手順の整備
